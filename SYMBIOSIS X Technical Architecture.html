One simulator, separate views

Build one deployable application with Python modules owned by different people. The mission package defines the route, crew, devices, timing and fixtures. The runtime simulates that plan. The twin accepts observations, workflows react, and the command gate controls changes to the simulated plant.

Solid lines carry model data, records or projections. Dashed lines carry simulated commands, Crew approval requests Ground advice and agent intents. P4 owns the writer and gate. P5 returns typed intents and never writes plant state directly. P1 owns the shared contract, integration and release.

The run, event order and database

  1. Load

    Validate the package. Freeze run ID, seed, schema, scenario, model and policy versions.

  2. Advance

    Advance integer mission seconds to the next target. Process intermediate due events even when the UI steps across them.

  3. Reduce

    Apply accepted observations first, then due deliveries. Dispatch subscribed workflows in stable order.

  4. Recheck

    At command time validate role, basis, expiry, freshness, phase and current feasibility. Prepare the authorized effect.

  5. Project

    Commit command and receipt atomically. Derive plant state from committed events, then refresh Crew and queue the filtered Ground snapshot. Reads never tick the clock.

SQLite owns the durable record

runs stores mission clock, status and revision. events is an ordered journal. operations stores idempotency key, normalized request digest and receipt. messages tracks due delivery and expiry. snapshots stores immutable role projections. Private payloads stay in a protected lane. Use indexed run and due-time lookups and a unique operation key per run and command scope. Start/reset keys are scoped to the authenticated caller and start endpoint because a run ID may not exist yet.

Keep effects atomic and replayable

Authorize the caller before resolving a prior receipt. Look up duplicates before cursor and closed-run guards. For a new operation use one short write transaction for clock, journal, command, receipt and relevant delivery state. Derive plant state from committed events. Reset closes the old run and starts a new one atomically. Use event_seq for order, decision_rev for applicability, and snapshot_id for exact evidence.

Ground sees only delivered allowlisted fields with sample, receive time and age. Never expose private check-in content, timing, IDs or gaps in a shared journal cursor. Reconnection and receipt of fresh evidence are separate. A rejected action may have an audit receipt while producing zero applied plant effects.

From component readings to a mission twin

Keep a component catalog, a sensor catalog and the observation stream separate. A sensor belongs to a device, crew member or environment zone. The 2D map resolves the same stable IDs the backend uses. The hardware for this build is simulated in software. An adapter can replay a supplied dataset through the same envelope.

  1. Simulate

    Each model advances its own state. Hidden truth is available to test fixtures.

  2. Observe

    Each virtual sensor samples on mission time. Apply configured noise, dropout or drift to readings.

  3. Validate

    Normalize unit and time. Retain source, quality and evidence. Invalid or out-of-order samples cannot silently replace accepted values.

  4. Aggregate

    Reduce readings into component, subsystem and mission views using explicit dependencies and freshness rules.

  5. Publish

    Crew gets the current allowed twin. Relay sends a separate operational snapshot. The workflow journal links back to its evidence.

Component and sensor records

Component records name entity_id, kind, owning subsystem, compartment or physical zone, and relationships such as powered_by and serves_zone. Sensor records name source_id, target entity, metric, canonical unit, sample period, input kind and privacy. The observation envelope keeps the current observed_at_s, received_at_s, model_version and payload quality. Example mapping: prototype cabin.co2 → source sim.cabin.co2, entity cabin-01, metric co2, unit ppm.

Aggregation rules

Aggregate domain quantities only where the model defines it. For example, add generation rates in a shared air zone and compute electrical headroom from modeled supply and load. For readiness, use required dependency checks with ready, blocked, unknown outcomes. Return the blocker and supporting event IDs. Missing data cannot turn a component green. Mission ETA can become conditional without changing the approved route.

Intake for the team’s component lists

For every supplied item record its stable ID, owning person, parent space or crew member, source, dependencies and status. For each reading record its unit, sample cadence, clock, quality and whether it is modeled, scripted, replayed or unavailable. Ask the owner to confirm what the reading may change in the model and which view can see it.

What makes a component ready to merge

Commit the catalog entry, a synthetic observation example, and an expected rollup result. Check both a normal sample and a stale or missing sample. If the component has no supported model yet, expose its location and capability with a clearly labeled unavailable value.

Seed and replay rules

Use a dedicated deterministic stream per sensor, derived from the run seed and stable source ID, or equivalent keyed sampling. Draw only on scheduled samples. Inspector clicks, API polling and a newly added sensor cannot perturb existing streams. Pin the model, policy, sensor profile and fixture versions. Compare stable events and role projections after stripping generated run IDs and wall-clock timestamps.

Generate the backup from the release

Export the five frames from the integrated engine with the fixture, versions and seed recorded. Compare saved and fresh replay frames in a test. The offline player shows these approved frames. Simulator truth and test-only fingerprints stay in test evidence. An action that fails a power check does not by itself prove the stale-advice gate was exercised.

What we took from P2. Use its zone inspectors, seeded sensor replay, explicit power → standby → removal → CO₂ chain, and saved-frame backup. The prototype’s 10 m³ and five-minute opening Ground age differ from the team contract’s 100 m³ and one-minute opening age. Keep the current default fixture and review the compact variant with P2/P4. Label the 3,200 ppm demo rule separately from NASA’s nominal one-hour average ppCO₂ reference. A one-hour reading needs supported pressure and sufficient time coverage. Local developer loop

The proposed README should pin the Python and Node versions and document installing the backend package, running uvicorn symbiosis_x.main:app, starting the Vite dev server with a proxy to /api, and running pytest and the production React build. Every laptop starts from the same base commit, a named scenario and its own seeded database.

Add a subsystem through its boundary

Add a typed observation or intent, register the trigger, add an asset and fixture, then add the projection field and inspector. Verify the old seed and the new case. A new dataset adapter or simulated subsystem leaves the API shape stable where possible.

Dependency direction is API → application → domain. Domain modules do not import FastAPI, React or SQLite. P5 wraps P4’s planner through a typed interface. Persistence implements the application’s needs and does not decide policy. Keep model constants in the versioned mission package when they can vary by fixture.

Abdelrahman’s workflow inside Sama’s backend

The P5 planning file adds a bounded tool registry, per-trigger agent runs and a dashboard trace. Use those inside the existing FastAPI application. Keep the proposal for eight tool steps and two sensor retries configurable until the team freezes its policy. Team agent workflow prototype

  1. Classify evidence

    Sama’s twin accepts or rejects readings and publishes a typed quality result.

  2. Monitor

    Abdelrahman’s Monitor deduplicates incident evidence and requests an allowed resample or assigns review.

  3. Planner agent

    Ask Sama’s deterministic planner for a revision-bound evaluation. Record reasons and who acts next.

  4. Relay

    Queue a filtered snapshot, deliver due messages, and hold advice that is stale, expired or invalid.

  5. Display and verify

    Suhad’s dashboard shows each handoff. Crew approval goes to Sama’s gate. A later reading verifies the effect.

When the remote is unavailable

Keep local Git and exchange git bundle files over the team’s local transfer path. On the sending checkout, create a bundle of the named branch with git bundle create team-a.bundle integration/sim. On the receiving checkout, run git bundle verify team-a.bundle, then git fetch team-a.bundle integration/sim:refs/heads/review/team-a. Review the diff before merging the review branch. If Git itself is unavailable, exchange only reviewed changed files with the baseline checksum and path manifest.
